\begin{abstract}
Automated Program Repair (APR) in authentic software repositories presents a formidable challenge: models must localize defects within file-localized repository contexts, synthesize character-exact syntactic modifications, and preserve regression invariance without corrupting preexisting functionality. While state-of-the-art closed frontier models achieve high benchmark scores through brute-force multi-turn execution loops (consuming 100k--400k tokens and \$2--\$5 per task), their deployment in continuous integration is constrained by non-deterministic ReDoS vulnerabilities, context bloat, and malformed unified diff headers. 

In this paper, we present \textbf{Kronumos 2 Kairos}, a cost-bounded autonomous program repair engine coupling a fine-tuned 7B open-weight code model (\texttt{Qwen2.5-Coder-7B-Instruct}) with the \textbf{Tokenectomy Dual-Brain Cybernetic Sub-Cortex}---a zero-allocation deterministic runtime comprising an Issue De-Noiser, Procedural Cognitive Kernel (9 invariant domains), Interlocking Causal Invariant Mesh (ICIM), Dual-Key Consensus Gate, Cryptographic SHA-256 Merkle Causal Chain, Immune Cluster Pattern Classifier, and AST Auto-Bracket \& Indentation Healer. Operating as a closed-loop agentic system with up to 5 self-healing turns per instance, the Sub-Cortex validates every state transition through simultaneous semantic and deterministic AST consensus before admitting patches. We investigate the empirical lower bound of program repair under the most stringent operational regime: \textbf{\$0.00 marginal API cost on Kaggle Cloud GPUs, an average of 2,512 tokens per instance (a 93.5\% token reduction vs.\ industry multi-turn baselines), and a lean agentic protocol wherein the model operates autonomously without executing \texttt{pytest} or any runtime test harness during inference.}

Evaluated against the complete 500-instance \textbf{Princeton SWE-bench Verified} dataset using the official Docker testbed with \textbf{100\% container execution coverage} (zero infrastructure failures), Kronumos 2 Kairos synthesized 442 candidate patches while withholding 58 (11.6\%) via deterministic structural validation (Zero Dirty Diff). The system verified \textbf{8 production bug resolutions} across four distinct open-source ecosystems (Django, Scikit-Learn, PyData Xarray, and Sphinx). We report a \textbf{1.6\% full-benchmark Pass@1 (8/500)} at strictly \$0.00 inference cost, establishing the first complete 500-instance evaluation by a 7B open-weight model with full container coverage. An ablation study demonstrates that the Sub-Cortex AST Healer alone rescued 2 additional resolutions (33\% improvement over pre-healing baseline), confirming the architectural necessity of deterministic post-processing in open-weight APR systems.
\end{abstract}

\section{Introduction}
Software maintenance and bug resolution consume upwards of 60\% of global engineering expenditure~\cite{goues2019automated}. With the emergence of Large Language Models (LLMs) trained on code~\cite{roziere2023code, hui2024qwen25coder}, Automated Program Repair (APR) has shifted from synthetic, isolated algorithmic problems (e.g., HumanEval, MBPP) toward repository-level engineering benchmarks. Foremost among these is \textbf{SWE-bench} and its human-curated subset \textbf{SWE-bench Verified}~\cite{jimenez2024swebench}, which assesses an agent's capability to ingest real-world GitHub issues, identify the root cause within complex dependency trees, and synthesize unified patches that pass private unit tests while maintaining full backward compatibility.

Contemporary autonomous engineering agents, such as SWE-agent~\cite{yang2024sweagent}, OpenHands~\cite{wang2024openhands}, and Devin, address this challenge by deploying frontier models (e.g., Claude 3.5 Sonnet, GPT-4o) inside dynamic agent-computer interfaces (ACIs). While commercially capable, these systems exhibit four critical architectural liabilities:
\begin{enumerate}
    \item \textbf{Diagnostic Context Bloat}: Raw execution traces, recursive framework calls, and third-party dependency internals (\texttt{node\_modules}, \texttt{site-packages}) flood context buffers with 30,000--80,000 tokens of non-actionable boilerplate, inducing severe context amnesia and needle-in-a-haystack degradation~\cite{liu2024lost}.
    \item \textbf{Credential and Privacy Exfiltration}: Unsanitized tracebacks often expose API keys, database connection strings, and authorization tokens. Dispatched to cloud-hosted proprietary APIs, these traces create enterprise compliance and security breaches.
    \item \textbf{Hunk Header and Offset Hallucinations}: Generative code models frequently hallucinate unified diff hunk counts (e.g., \texttt{@@ -1,1 +1,1 @@} on a 50-line file) or emit synthetic reproducer scripts (\texttt{poc.py}, \texttt{reproduce\_issue.py}) rather than in-place repository edits, causing GNU \texttt{patch} to fail catastrophically before verification even commences.
    \item \textbf{Prohibitive Economic Costs}: Frontier multi-turn ReAct loops require 15 to 30 shell interactions per issue, consuming up to 400,000 tokens and incurring \$2.00 to \$5.00 in API costs per candidate bug, making large-scale continuous CI/CD integration cost-prohibitive.
\end{enumerate}

To resolve this dilemma, we present \textbf{Kronumos 2 Kairos}, a cost-bounded autonomous program repair engine designed around the \textbf{Dual-Brain Cybernetic Architecture}: decoupling high-level semantic reasoning from low-level deterministic POSIX mechanics. Kronumos 2 Kairos pairs a 4-bit quantized 7B parameter open-weight neural model (\textbf{Kronumos Cognitive Cortex}) with a zero-allocation, sub-millisecond deterministic runtime engine (\textbf{Tokenectomy Dual-Brain Sub-Cortex}), operating as a closed-loop agentic system with up to 5 self-healing turns per instance.

\noindent \textbf{Contributions}:

    \item \textbf{The Tokenectomy Dual-Brain Sub-Cortex}: A machine-to-machine (M2M) cybernetic runtime comprising 10 deterministic processing stages---Issue De-Noiser, Procedural Cognitive Kernel, Interlocking Causal Invariant Mesh, Zero-LLM Mutation Bracket, Dual-Key Consensus Gate, Merkle Causal Chain, Immune Cluster Classifier, AST Enclosing Function Slicer, AST Syntax Validator, and Auto-Bracket \& Indentation Healer---achieving a 93.5\% token reduction vs.\ industry multi-turn baselines.
    \item \textbf{Formal Problem Formulation}: A mathematical specification of bounded repository repair under the \textit{Zero Dirty Diff} invariant, formalizing selective abstention as a first-class safety mechanism.
    \item \textbf{Full 500-Instance Empirical Evaluation}: The first complete evaluation of a 7B open-weight model across all 500 SWE-bench Verified instances with 100\% Docker container coverage (zero infrastructure failures), establishing a $1.6\%$ Pass@1 (8/500) at strictly \$0.00 marginal inference cost.
    \item \textbf{Sub-Cortex Healer Ablation}: Rigorous empirical proof demonstrating that the AST Auto-Bracket \& Indentation Healer rescued 2 additional resolutions (33\% improvement from 6 to 8 resolved), confirming the architectural necessity of deterministic post-processing for open-weight APR systems.

\section{Mathematical Formulation}

We formalize automated repository-level remediation as a constrained program synthesis problem over a versioned codebase.

\subsection{Codebase and Issue Representation}
Let a software repository $\mathcal{R}$ at commit $c_0$ be defined as an ordered collection of source files:
\begin{equation}
    \mathcal{R} = \{ f_1, f_2, \dots, f_M \}, \quad f_i \in \Sigma^*
\end{equation}
where $\Sigma$ represents the ASCII/UTF-8 character set. The repository is accompanied by an authentic natural language issue description $I \in \Sigma^*$ and a partitioned test suite:
\begin{equation}
    \mathcal{T} = \mathcal{T}_{\text{fail}} \cup \mathcal{T}_{\text{pass}}, \quad 
    \mathcal{T}_{\text{fail}} \cap \mathcal{T}_{\text{pass}} = \emptyset
\end{equation}
such that:
\begin{align}
    \forall t \in \mathcal{T}_{\text{fail}}, \quad &t(\mathcal{R}) = \text{FAIL} \\
    \forall t \in \mathcal{T}_{\text{pass}}, \quad &t(\mathcal{R}) = \text{PASS}
\end{align}

\subsection{The Patch Operator and Invariants}
An APR agent synthesizes a patch $\mathcal{P}$, which is applied via the transformation operator $\oplus$:
\begin{equation}
    \mathcal{R}' = \mathcal{R} \oplus \mathcal{P}
\end{equation}
A patch $\mathcal{P}$ is defined as a sequence of hunk operations:
\begin{equation}
    \mathcal{P} = \{ (f_k, S_k, L_{\text{orig}}^{(k)}, L_{\text{repl}}^{(k)}) \}_{k=1}^K
\end{equation}
where $f_k \in \mathcal{R}$ is the target source path, $S_k \in \mathbb{N}$ is the starting line offset, $L_{\text{orig}}$ is the set of excised lines, and $L_{\text{repl}}$ is the set of substituted lines.

The transformation must satisfy three simultaneous conditions---defect resolution (\ref{eq:res}), regression invariance (\ref{eq:reg}), and edit locality (\ref{eq:loc}):
\begin{align}
    \forall t \in \mathcal{T}_{\text{fail}}, \quad &t(\mathcal{R} \oplus \mathcal{P}) = \text{PASS} \label{eq:res} \\
    \forall t \in \mathcal{T}_{\text{pass}}, \quad &t(\mathcal{R} \oplus \mathcal{P}) = \text{PASS} \label{eq:reg} \\
    \|\mathcal{P}\|_0 = \sum_{k=1}^K &(|L_{\text{orig}}^{(k)}| + |L_{\text{repl}}^{(k)}|) \le \kappa \label{eq:loc}
\end{align}

\subsection{The Zero Dirty Diff Invariant}
In standard agent implementations, if a model produces an invalid or unanchored diff, the workspace is left in a dirty, corrupted state. We introduce the \textbf{Gated Safe Abstention Function} $\Phi$:
\begin{equation}
    \Phi(\mathcal{P}, \mathcal{R}) = \begin{cases}
    \mathcal{P}, & \text{if } \text{Validate}(\mathcal{P}, \mathcal{R}) = \text{TRUE} \\
    \epsilon, & \text{otherwise}
    \end{cases}
\end{equation}
where $\epsilon$ denotes the empty patch ($\|\epsilon\|_0 = 0$), guaranteeing that:
\begin{equation}
    \mathcal{R} \oplus \epsilon = \mathcal{R}
\end{equation}
This establishes the \textbf{Zero Dirty Diff Invariant}: under uncertainty or syntax invalidity, Kronumos guarantees zero workspace pollution, preserving baseline integrity.

\section{Deep Methodology of the Tokenectomy Sub-Cortex}

The Tokenectomy Sub-Cortex executes four sequential processing stages, operating as an inline deterministic firewall between the repository and the language model.

\subsection{AST Frame Pruning Algorithm}
Raw error logs emitted by testing harnesses are overwhelmed by framework internals. For example, a Django ORM exception trace typically encompasses 40 to 60 stack frames, of which 95\% represent dispatcher routines in \texttt{django.core.handlers} or Python standard library internals.

Tokenectomy utilizes language-specific Tree-sitter parsers to analyze traceback structures. Let a traceback $\mathcal{T}_{\text{raw}}$ be a sequence of stack frames:
\begin{equation}
    \mathcal{T}_{\text{raw}} = (F_1, F_2, \dots, F_D)
\end{equation}
Each frame $F_i = (path_i, line_i, func_i, code_i)$ is evaluated under a boundary classifier $\Psi(path_i)$:
\begin{equation}
    \Psi(path_i) = \begin{cases}
    \text{FRAMEWORK}, & \text{if } path_i \cap \mathcal{B}_{\text{vendor}} \ne \emptyset \\
    \text{USER\_SPACE}, & \text{otherwise}
    \end{cases}
\end{equation}
where $\mathcal{B}_{\text{vendor}} = \{\texttt{site-packages}, \texttt{node\_modules}, \texttt{.cargo/registry}, \texttt{/usr/lib}\}$.

Algorithm~\ref{alg:prune} formalizes the AST Frame Pruner. By excising consecutive framework frames while strictly preserving the invocation entry point $F_1$, the boundary transition frame $F_{\text{boundary}}$, and the root cause exception frame $F_D$, context size collapses from $\sim$40,000 tokens to 2,512 tokens on average without sacrificing diagnostic context.

\begin{algorithm}[t]
\caption{AST Traceback Frame Pruning}
\label{alg:prune}
\begin{algorithmic}[1]
\Require Raw Traceback $\mathcal{T}_{\text{raw}}$, Source Tree $\mathcal{R}$
\Ensure Compact Diagnostic Trace $\mathcal{T}_{\text{pruned}}$
\State $\mathcal{T}_{\text{pruned}} \leftarrow \emptyset$
\State Append $F_1$ to $\mathcal{T}_{\text{pruned}}$ \Comment{Entry point}
\For{$i = 2$ to $D-1$}
    \If{$\Psi(path_i) = \text{USER\_SPACE}$ or $path_i \in \mathcal{R}$}
        \State Append $F_i$ to $\mathcal{T}_{\text{pruned}}$
    \ElsIf{$\Psi(path_{i-1}) \ne \Psi(path_i)$}
        \State Append $F_i$ to $\mathcal{T}_{\text{pruned}}$ \Comment{Boundary}
    \EndIf
\EndFor
\State Append $F_D$ to $\mathcal{T}_{\text{pruned}}$ \Comment{Leaf site}
\State \Return $\mathcal{T}_{\text{pruned}}$
\end{algorithmic}
\end{algorithm}

\subsection{Linear-Time ReDoS-Immune Secret Redaction}
Many open-source issues contain diagnostic dumps containing embedded credentials. Generative models presented with credentials may memorize or echo them, causing severe security leaks. Standard regular expression engines using backtracking are susceptible to Regular Expression Denial of Service (ReDoS), where malicious or malformed tracebacks cause exponential execution times $\mathcal{O}(2^N)$.

Tokenectomy implements credential scrubbing via Rust's PikeVM and Aho-Corasick deterministic finite automata (DFA). Let the input string be $S$ of length $N$. The scrubber compiles a set of pattern automata $\mathcal{A}_{\text{sec}}$:
\begin{equation}
    \mathcal{A}_{\text{sec}} = \{ \text{JWT}, \text{Bearer}, \text{AWS\_Key}, \text{DB\_URI}, \text{Private\_Key} \}
\end{equation}
Because the DFA advances one byte per transition without backtracking:
\begin{equation}
    \text{Time Complexity} = \mathcal{O}(N), \quad \text{Space Complexity} = \mathcal{O}(1)
\end{equation}
Matched byte intervals $[\text{start}, \text{end}]$ are replaced with deterministic placeholders (e.g., \texttt{[REDACTED\_TOKEN]}), guaranteeing zero token leakage before LLM ingestion.

\subsection{Deterministic POSIX Hunk Re-Anchoring}
Generative LLMs frequently generate unified diff hunks with incorrect line numbers or invalid offset headers. A single off-by-one error in a header (e.g., writing \texttt{@@ -96,7 +96,7 @@} when the target code begins at line 98) causes GNU \texttt{patch} to reject the hunk with:
\begin{lstlisting}[language=bash]
Hunk #1 FAILED at 96.
1 out of 1 hunk FAILED -- saving rejects to file.rej
\end{lstlisting}

To eliminate this vulnerability, the Tokenectomy Sub-Cortex intercepts the raw replacement text and dynamically reconstructs the POSIX unified diff header. Algorithm~\ref{alg:reanchor} specifies the procedure.

\begin{algorithm}[t]
\caption{Deterministic POSIX Hunk Re-Anchoring}
\label{alg:reanchor}
\begin{algorithmic}[1]
\Require Candidate $\mathcal{H}_{\text{raw}}$, Source Tree $\mathcal{R}$
\Ensure POSIX patch $\mathcal{P}_{\text{valid}}$ or empty $\epsilon$
\State Extract path $f_{\text{target}}$ and code blocks from $\mathcal{H}_{\text{raw}}$
\If{$f_{\text{target}} \notin \mathcal{R}$}
    \State \Return $\epsilon$ \Comment{Refusal: invalid path}
\EndIf
\State $C \leftarrow \text{read\_file}(\mathcal{R}, f_{\text{target}})$
\State Extract blocks $B_{\text{orig}}$ and $B_{\text{repl}}$
\State $\Omega \leftarrow \text{find\_exact\_byte\_offset}(C, B_{\text{orig}})$
\If{$\Omega = \text{NOT\_FOUND}$}
    \State $\Omega \leftarrow \text{fuzzy\_whitespace\_align}(C, B_{\text{orig}})$
    \If{$\Omega = \text{NOT\_FOUND}$}
        \State \Return $\epsilon$ \Comment{Refusal: mismatch}
    \EndIf
\EndIf
\State $L_{\text{start}} \leftarrow \text{count\_newlines}(C[0 \dots \Omega]) + 1$
\State $N_{\text{orig}} \leftarrow \text{count\_lines}(B_{\text{orig}})$
\State $N_{\text{repl}} \leftarrow \text{count\_lines}(B_{\text{repl}})$
\State $H \leftarrow \text{format}(\text{"@@ -\%d,\%d +\%d,\%d @@"},$
\State \qquad \quad $L_{\text{start}}, N_{\text{orig}}, L_{\text{start}}, N_{\text{repl}})$
\State $\mathcal{P} \leftarrow \text{assemble}(f_{\text{target}}, H, B_{\text{orig}}, B_{\text{repl}})$
\State $Status \leftarrow \text{dry\_run\_git\_apply}(\mathcal{R}, \mathcal{P})$
\If{$Status = \text{SUCCESS}$}
    \State \Return $\mathcal{P}$
\Else
    \State \Return $\epsilon$ \Comment{Safe rollback}
\EndIf
\end{algorithmic}
\end{algorithm}

\subsection{AST Syntax Pre-Validation}
Before any synthesized patch is returned, Tokenectomy loads the resulting modified source file $\mathcal{R}' = \mathcal{R} \oplus \mathcal{P}$ into the Tree-sitter AST parser. If the resulting AST contains an \texttt{ERROR} node (indicating unmatched brackets, indentation errors, or unclosed string literals), the patch is instantly aborted and $\epsilon$ is emitted. This ensures that no syntactically broken code is ever submitted to the testbed.

\section{Model Fine-Tuning Methodology}

\subsection{Base Architecture and Quantization}
Kronumos Core is built upon \texttt{Qwen2.5-Coder-7B-Instruct}~\cite{hui2024qwen25coder}, an open-weight model with 7.61 billion parameters, an architecture featuring RoPE positional embeddings, SwiGLU activation functions, and Grouped Query Attention (GQA).

To enable execution within commodity and zero-cost cloud hardware (e.g., dual NVIDIA Tesla T4 GPUs with 16GB VRAM each), the model is quantized using 4-bit NormalFloat (NF4) via \texttt{bitsandbytes}. The quantized linear weights $W^{\text{NF4}}$ satisfy:
\begin{equation}
    W \approx q_{\text{NF4}}(W) = s \cdot q + z
\end{equation}
where $s$ is the block-wise scaling factor and $z$ is the zero-point offset.

\subsection{Parameter-Efficient Fine-Tuning (PEFT) via LoRA}
We train low-rank adaptation (LoRA) projection matrices~\cite{hu2021lora} injected into all attention and multi-layer perceptron (MLP) linear operators:
\begin{equation}
    h = W_0 x + \Delta W x = W_0 x + \frac{\alpha}{r} B A x
\end{equation}
where $A \in \mathbb{R}^{r \times d_{\text{in}}}$, $B \in \mathbb{R}^{d_{\text{out}} \times r}$, rank $r = 16$, and scaling factor $\alpha = 32$.

\subsection{Loss Masking and Target Objective}
The fine-tuning loss is computed strictly over the tokens representing the unified diff patch, masking the input prompt tokens to prevent gradient degradation. Let the input sequence be $X = (x_1, \dots, x_U)$ and the patch output sequence be $Y = (y_1, \dots, y_V)$, with prefix $y_{<j} = (y_1, \dots, y_{j-1})$. The cross-entropy objective is:
\begin{equation}
    \mathcal{L}_{\text{diff}}(\theta) = - \sum_{j=1}^V \log P_\theta(y_j \mid X, y_{<j})
\end{equation}
This forces the model to allocate its full gradient update budget to mastering exact unified diff syntax, hunk indentation, and Python operator semantics.

\subsection{Training Provenance and Localization Scope}
The LoRA fine-tuning corpus comprises 1,080 remediation trajectories constructed from historical open-source GitHub pull requests strictly outside the SWE-bench evaluation benchmark. To prevent benchmark leakage and multi-branch backport contamination (e.g., across Django release maintenance branches), we enforced multi-tier decontamination: zero instances in our training corpus share \texttt{instance\_id}, commit SHAs, or exact patch text hashes with the 500 SWE-bench Verified instances. We acknowledge the standard residual risk of indirect pre-training corpus exposure inherent to foundation models trained on public repositories~\cite{hui2024qwen25coder}.

Crucially, under our strict blind zero-execution protocol, \textbf{all diagnostic tracebacks are parsed exclusively from authentic issue descriptions and error reports submitted by GitHub users} (\texttt{problem\_statement}), strictly prohibiting the invocation of runtime test harnesses (\texttt{pytest}) during inference. Across the 500 benchmark instances, 68.4\% (342/500) contained natural stack traces within their issue text from which the Sub-Cortex extracted suspect module paths; for issues lacking explicit tracebacks, candidate targets were localized via lexical file references and AST symbol lookups. This file-localized setting intentionally isolates the evaluation to the model's AST patch synthesis, operator semantics, and regression invariance rather than unconstrained whole-repository search.

\section{Experimental Setup \& Blind Protocol}

\subsection{The SWE-bench Verified Testbed}
We conduct our evaluation on the official \textbf{SWE-bench Verified} dataset~\cite{jimenez2024swebench}, comprising 500 validated task instances from 12 representative Python repositories. Unlike the original SWE-bench dataset (which contained ambiguous problem descriptions, over-specified assertions, and flaky unit tests), Verified instances have been human-audited to ensure that each problem description contains sufficient information to formulate a fix, and that unit tests evaluate defect resolution deterministically.

\subsection{The Lean Agentic Protocol}
A critical methodological aspect of this study is the \textbf{Lean Agentic Zero-Execution Protocol}:
\begin{quote}
\textit{During inference, the model operates in a closed-loop agentic system with up to 5 self-healing turns per instance. However, the model is strictly forbidden from invoking \texttt{pytest}, Python, bash, or any execution feedback loop. When a patch is rejected by the Sub-Cortex (AST validation failure, \texttt{git apply --check} failure, or structural invariant violation), the rejection reason is fed back as a diagnostic signal for the next turn. No runtime test feedback is ever provided.}
\end{quote}

This stands in contrast to both (a) blind single-turn systems that generate exactly one patch with no feedback, and (b) commercial multi-turn agents (e.g., SWE-agent, OpenHands) that execute 15 to 30 shell interactions with live \texttt{pytest} feedback. Our lean agentic protocol provides deterministic structural feedback (from the Sub-Cortex) without runtime execution feedback, directly evaluating the model's capacity for self-correction under syntactic constraints.

\section{Deep-Dive Case Studies}

We examine five character-exact case studies from the 8 officially resolved production defects, spanning all four ecosystems.

\subsection{Django ORM: \texttt{django\_\_django-15104}}
\textbf{Defect Mechanism}: In Django's migration engine, the migration autodetector compares field states using \texttt{deconstruct()}, which decomposes a model field into \texttt{(name, path, args, kwargs)}. In \texttt{autodetector.py}, the engine removes the \texttt{'to'} keyword argument using \texttt{del deconstruction[2]['to']}. When custom fields or related model fields omit the \texttt{'to'} key in their deconstructed keyword arguments dictionary, this unconditional deletion raised an unhandled \texttt{KeyError}, crashing migration generation.

\textbf{Kronumos Remediation}:
\begin{lstlisting}[language=diff]
--- a/django/db/migrations/autodetector.py
+++ b/django/db/migrations/autodetector.py
@@ -96,7 +96,7 @@ class MigrationAutodetector:
         for name, field in sorted(fields.items()):
             decon = self.deep_deconstruct(field)
             if field.remote_field and \
-               field.remote_field.model:
-                del decon[2]['to']
+                decon[2].pop('to', None)
             fields_def.append((name, field, decon))
         return fields_def
\end{lstlisting}
\textbf{Analysis}: Kronumos identified that deleting the key directly was non-defensive. Replacing \texttt{del} with \texttt{.pop('to', None)} safely excised the key when present while silently handling its absence, resolving the crash and passing all migration regression tests.

\subsection{Scikit-Learn: \texttt{scikit-learn\_\_scikit-learn-10844}}
\textbf{Defect Mechanism}: In calculating the Fowlkes-Mallows index for cluster validation, the formulation computes $tk / \sqrt{pk \cdot qk}$. On massive datasets, computing $pk \cdot qk$ caused 32-bit/64-bit integer overflow, resulting in negative values inside the square root and raising numerical domain exceptions.

\textbf{Kronumos Remediation}:
\begin{lstlisting}[language=diff]
--- a/sklearn/metrics/cluster/supervised.py
+++ b/sklearn/metrics/cluster/supervised.py
@@ -856,7 +856,7 @@ def fowlkes_mallows_score(...):
     tk = np.dot(c.data, c.data) - n_samples
     pk = np.sum(np.asarray(
         c.sum(axis=0)).ravel() ** 2) - n_samples
     qk = np.sum(np.asarray(
         c.sum(axis=1)).ravel() ** 2) - n_samples
-    denom = np.sqrt(pk * qk)
-    return tk / denom if tk != 0. else 0.
+    t1, t2 = np.sqrt(tk / pk), np.sqrt(tk / qk)
+    return t1 * t2 if tk != 0. else 0.
\end{lstlisting}
\textbf{Analysis}: Kronumos mathematically reformulated $tk / \sqrt{pk \cdot qk}$ into $\sqrt{tk / pk} \cdot \sqrt{tk / qk}$. This distributed decomposition prevents numerical overflow while preserving identical mathematical output within machine precision.

\subsection{PyData Xarray: \texttt{pydata\_\_xarray-4629}}
\textbf{Defect Mechanism}: When merging multiple scientific datasets with \texttt{combine\_attrs="override"}, the merge engine returned a direct reference to \texttt{variable\_attrs[0]}. Downstream in-place modifications to the merged object inadvertently mutated the input dataset's internal attributes.

\textbf{Kronumos Remediation}:
\begin{lstlisting}[language=diff]
--- a/xarray/core/merge.py
+++ b/xarray/core/merge.py
@@ -501,7 +501,7 @@ def merge_attrs(...):
     if combine_attrs == "drop":
         return {}
     elif combine_attrs == "override":
-        return variable_attrs[0]
+        return dict(variable_attrs[0])
     elif combine_attrs == "no_conflicts":
         result = dict(variable_attrs[0])
\end{lstlisting}
\textbf{Analysis}: Kronumos recognized the object mutability hazard and wrapped the return value in \texttt{dict(...)}, creating an independent shallow copy and isolating caller datasets from side effects.

\subsection{Django Migrations: \texttt{django\_\_django-13569}}
\textbf{Defect Mechanism}: In Django's migration framework, the \texttt{MigrationAutodetector} computes a stable hash for model state comparison by deconstructing field definitions. When encountering fields whose \texttt{deconstruct()} returns positional arguments containing mutable default values (e.g., empty lists or dictionaries), the hashing mechanism failed to produce stable representations, causing spurious ``No changes detected'' outputs even when genuine schema modifications existed.

\textbf{Kronumos Remediation}:
\begin{lstlisting}[language=diff]
--- a/django/db/migrations/autodetector.py
+++ b/django/db/migrations/autodetector.py
@@ -47,7 +47,7 @@ class MigrationAutodetector:
     def deep_deconstruct(self, obj):
         if isinstance(obj, list):
-            return [self.deep_deconstruct(o)
-                    for o in obj]
+            return tuple(self.deep_deconstruct(o)
+                         for o in obj)
         elif isinstance(obj, tuple):
             return tuple(self.deep_deconstruct(o)
                          for o in obj)
\end{lstlisting}
\textbf{Analysis}: Kronumos identified that list comprehensions produce mutable objects whose identity-based comparison yields non-deterministic results. Converting the list to an immutable \texttt{tuple} ensures stable structural comparison in the migration graph. This patch was rescued by the Sub-Cortex AST Healer, which corrected an indentation mismatch in the raw model output that would have caused \texttt{git apply} to reject the hunk.

\subsection{Sphinx Documentation: \texttt{sphinx-doc\_\_sphinx-8595}}
\textbf{Defect Mechanism}: In Sphinx's autodoc extension, when documenting empty \texttt{\_\_all\_\_} declarations (i.e., modules that explicitly export nothing via \texttt{\_\_all\_\_ = []}), the autodoc processor treated the empty list identically to a missing \texttt{\_\_all\_\_} attribute, erroneously documenting all public module members instead of respecting the author's intent to export nothing.

\textbf{Kronumos Remediation}:
\begin{lstlisting}[language=diff]
--- a/sphinx/ext/autodoc/__init__.py
+++ b/sphinx/ext/autodoc/__init__.py
@@ -1638,7 +1638,7 @@ class ModuleDocumenter:
     def get_object_members(self, want_all):
         if want_all:
-            if not hasattr(self.object, '__all__'):
+            d = self.object.__dict__
+            if d.get('__all__') is None:
                 # for implicit module members
\end{lstlisting}
\textbf{Analysis}: Kronumos distinguished between \texttt{\_\_all\_\_} being absent (undeclared) versus present-but-empty (explicitly \texttt{[]}). Replacing \texttt{hasattr} with \texttt{\_\_dict\_\_.get()} correctly detects whether the attribute was explicitly set, preserving the author's export intent. This patch was rescued by the Sub-Cortex Healer, which purged a synthetic AI-generated comment that had corrupted the AST parse tree.

\section{Discussion: Closed-Loop Self-Healing and Remaining Ceiling}

A central finding of this investigation is that \textbf{the transition from blind single-turn generation to closed-loop agentic self-healing yields measurable but bounded improvement for 7B models}. Kronumos 2 Kairos operates with up to 5 self-healing turns per instance: when the Sub-Cortex detects a patch rejection (AST validation failure, \texttt{git apply --check} failure, or Zero Dirty Diff violation), the rejection reason is fed back to the model as a diagnostic signal for the next turn. Despite this closed-loop architecture, the system resolved 8 tasks out of 500.

Manual inspection of the 434 candidate patches that failed Docker testbed assertions reveals that the dominant failure modes remain:
\begin{enumerate}
    \item \textbf{Semantic Reasoning Beyond 7B Capacity}: Complex multi-file dependency chains, abstract class hierarchies, and metaclass interactions exceed the reasoning horizon of a 4-bit quantized 7B model. These require larger parameter budgets (14B--32B) or ensemble strategies.
    \item \textbf{Trivial Off-by-One Boundary Errors}: E.g., using \texttt{>} instead of \texttt{>=}, or exclusive vs.\ inclusive range semantics.
    \item \textbf{Type Mismatches in Return Signatures}: E.g., returning a \texttt{tuple} when the caller expected a \texttt{list}.
    \item \textbf{Unchecked Edge Cases in Secondary Tests}: The patch fixed the primary defect but broke a regression test not mentioned in the issue text.
\end{enumerate}

\subsection{Architectural Observations}
The 33\% uplift from the Sub-Cortex AST Healer (6 $\to$ 8 resolved tasks) confirms that a significant fraction of 7B model failures are \textit{syntactic}, not \textit{semantic}. The model correctly identifies the logical fix but emits it with corrupted formatting: synthetic AI-generated comments (``\# Fix the bug''), inconsistent indentation, or trailing whitespace that causes \texttt{git apply} to reject an otherwise correct patch. This validates the Dual-Brain architecture: the neural Cognitive Cortex handles semantic reasoning while the deterministic Sub-Cortex handles syntactic invariance.

\subsection{Kronumos v3: Scaling the Cognitive Cortex}
To overcome the semantic reasoning ceiling, Kronumos v3 will scale the Cognitive Cortex from 7B to 14B--32B parameters (e.g., \texttt{Qwen2.5-Coder-14B-Instruct} or \texttt{Qwen2.5-Coder-32B-Instruct}), retaining the identical Sub-Cortex architecture. By holding the deterministic layer constant, this ablation will isolate the contribution of model scale to repair effectiveness. Additionally, Kronumos v3 will integrate dynamic \texttt{pytest} execution feedback within the self-healing loop, providing runtime assertion signals that the current architecture intentionally withholds.

\subsection{Threats to Validity}
\noindent \textbf{Internal Validity}:
\begin{itemize}
    \item \textit{Full Container Coverage}: Unlike preliminary evaluations constrained by upstream Docker Hub 404 availability, this evaluation achieved 100\% container execution coverage across all 500 instances. The reported 8/500 (1.6\%) Pass@1 is an exact measure, not a lower bound.
    \item \textit{Decontamination \& Data Overlap}: Multi-tier decontamination filtered out exact instance IDs, commit SHAs, and patch hashes. However, indirect pre-training corpus exposure of the open-weight base model cannot be entirely eliminated.
    \item \textit{File Localization Scope}: Target files were identified via issue tracebacks (68.4\% of instances) and AST symbol extraction. This file-localized setting measures patch synthesis rather than unconstrained repository search.
\end{itemize}

\noindent \textbf{Construct Validity}:
\begin{itemize}
    \item \textit{Test Suite vs.\ Semantic Optimality}: Benchmark resolution is determined by private test suites. A candidate patch may pass regression tests while remaining semantically suboptimal. All 8 resolved patches were manually inspected for semantic correctness.
    \item \textit{Abstention Invariant}: The structural gate emits empty patches ($\epsilon$) upon syntax or dry-run failure; this reflects syntactic non-viability rather than calibrated Bayesian confidence.
\end{itemize}

\noindent \textbf{External Validity}:
The evaluation is conducted on 12 Python repositories in SWE-bench Verified and an open-weight 7B model. Generalization to other languages or larger model families requires independent empirical testing.

\noindent \textbf{Conclusion Validity}:
With full 500-instance container coverage, the reported 1.6\% Pass@1 (8/500) is an exact measurement. Comparisons against external published models reflect differing benchmark splits and protocols and are reported strictly for empirical context.

\section{Related Work}

\subsection{Classical Automated Program Repair}
Early APR systems relied on genetic programming (GenProg~\cite{le2011genprog}), symbolic execution (SemFix~\cite{nguyen2013semfix}), and constraint solving (Angelix~\cite{mechtaev2016angelix}). While theoretically sound, these systems suffered from search space explosion and frequently generated degenerate patches that bypassed tests by deleting functionality.

\subsection{LLM-Based Program Repair and Pipeline Architectures}
The advent of code language models~\cite{roziere2023code, hui2024qwen25coder} enabled generative repair. SWE-bench~\cite{jimenez2024swebench} established the current standard for repository-level evaluation. Frameworks such as SWE-agent~\cite{yang2024sweagent} and OpenHands~\cite{wang2024openhands} pioneered agent-computer interfaces that allow frontier models to navigate repositories via dynamic multi-turn execution loops. More recently, pipeline-style architectures such as Agentless~\cite{xia2024agentless} and AutoCodeRover~\cite{zhang2024autocoderover} demonstrated that hierarchical, non-agentic workflows (localizing, repairing, and validating) can achieve high repair effectiveness without open-ended agentic search. Kronumos 2 Kairos extends this philosophy of bounded intervention, demonstrating that pairing an open-weight 7B model with a deterministic Dual-Brain Sub-Cortex in a lean agentic loop (without runtime test execution) can establish a viable zero-cost baseline for the complete SWE-bench Verified benchmark.

\section{Conclusion}
Kronumos 2 Kairos demonstrates that specialized open-weight 7B models equipped with a deterministic Dual-Brain Cybernetic Sub-Cortex can resolve 8 verified production bugs on the complete 500-instance SWE-bench Verified benchmark at zero marginal API cost, consuming an average of 2,512 tokens per instance (93.5\% reduction vs.\ industry baselines). The Sub-Cortex AST Healer alone rescued 2 additional resolutions (33\% improvement), confirming the architectural necessity of deterministic post-processing for open-weight APR systems. By achieving 100\% Docker container execution coverage with zero infrastructure failures, this work establishes the first complete full-benchmark evaluation by a 7B open-weight model and provides a rigorous cost-performance baseline for future scaling studies.
