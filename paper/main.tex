\begin{abstract}
Automated Program Repair (APR) in authentic software repositories presents a formidable challenge: agents must localize bugs across tens of thousands of lines of code, synthesize character-exact syntactic modifications, and preserve regression invariance without corrupting preexisting functionality. While state-of-the-art closed frontier models achieve high benchmark scores through brute-force multi-turn execution loops (consuming 100k--400k tokens and \$2--\$5 per task), their deployment in enterprise production is severely constrained by non-deterministic ReDoS vulnerabilities, credential leaks, context bloat, and malformed unified diff headers. 

In this paper, we present \textbf{Kronumos}, an autonomous software engineering remediation framework coupling a fine-tuned 7B open-weight code model (\texttt{Qwen2.5-Coder-7B-Instruct}) with the \textbf{Tokenectomy M2M Sub-Cortex}---a zero-allocation Rust runtime engine engineered for sub-millisecond AST traceback pruning, $\mathcal{O}(N)$ ReDoS-immune secret redaction, and deterministic POSIX unified diff re-anchoring. We investigate the empirical lower bound of autonomous repair under the most stringent operational regime possible: \textbf{\$0.00 marginal API cost on Kaggle Cloud GPUs, an average of 3,009.3 tokens per instance (a 92.2\% token reduction vs.\ raw model context), and a strict blind single-turn protocol wherein the model is strictly forbidden from executing \texttt{pytest}, Python, or any runtime feedback harness during inference.}

Evaluated against the complete 500-instance \textbf{Princeton SWE-bench Verified} dataset, Kronumos officially resolved \textbf{10 real-world production issues} across five core open-source ecosystems (Django, Scikit-Learn, Pytest, PyData Xarray, and SymPy) within the official Princeton Docker testbed. We report a \textbf{12.66\% candidate precision (10/79)} and a \textbf{2.0\% full-benchmark Pass@1 (10/500)} with \textbf{100.0\% GNU patch compliance (0 syntax or hunk errors)}. Of the 500 instances, the confidence gate withheld patches for 421 (84.2\%), ensuring zero workspace pollution at the cost of lower recall. We formalize the mathematical problem of bounded repository repair, detail the architectural mechanisms of the Rust Sub-Cortex, provide an empirical ablation demonstrating how deterministic re-anchoring rescues raw model outputs from 100\% hunk rejection, present character-exact case studies of resolved bugs, and establish the architectural bridge to multi-turn verification in Kronumos v2.
\end{abstract}

\section{Introduction}
Software maintenance and bug resolution consume upwards of 60\% of global engineering expenditure~\cite{goues2019automated}. With the emergence of Large Language Models (LLMs) trained on code~\cite{roziere2023code, hui2024qwen25coder}, Automated Program Repair (APR) has shifted from synthetic, isolated algorithmic problems (e.g., HumanEval, MBPP) toward repository-level engineering benchmarks. Foremost among these is \textbf{SWE-bench} and its human-curated subset \textbf{SWE-bench Verified}~\cite{jimenez2024swebench}, which assesses an agent's capability to ingest real-world GitHub issues, identify the root cause within complex dependency trees, and synthesize unified patches that pass private unit tests while maintaining full backward compatibility.

Contemporary autonomous engineering agents, such as SWE-agent~\cite{yang2024sweagent}, OpenHands~\cite{wang2024openhands}, and Devin, address this challenge by deploying frontier models (e.g., Claude 3.5 Sonnet, GPT-4o) inside dynamic agent-computer interfaces (ACIs). While commercially capable, these systems exhibit four critical architectural liabilities:
\begin{enumerate}
    \item \textbf{Diagnostic Context Bloat}: Raw execution traces, recursive framework calls, and third-party dependency internals (\texttt{node\_modules}, \texttt{site-packages}) flood context buffers with 30,000--80,000 tokens of non-actionable boilerplate, inducing severe context amnesia and needle-in-a-haystack degradation~\cite{liu2024lost}.
    \item \textbf{Credential and Privacy Exfiltration}: Unsanitized tracebacks often expose API keys, database connection strings, and authorization tokens. Dispatched to cloud-hosted proprietary APIs, these traces create enterprise compliance and security breaches.
    \item \textbf{Hunk Header and Offset Hallucinations}: Generative code models frequently hallucinate unified diff hunk counts (e.g., \texttt{@@ -1,1 +1,1 @@} on a 50-line file) or emit synthetic reproducer scripts (\texttt{poc.py}, \texttt{reproduce\_issue.py}) rather than in-place repository edits, causing GNU \texttt{patch} to fail catastrophically before verification even commences.
    \item \textbf{Prohibitive Economic Costs}: Frontier multi-turn ReAct loops require 15 to 30 shell interactions per issue, consuming up to 400,000 tokens and incurring \$2.00 to \$5.00 in API costs per candidate bug, making large-scale continuous CI/CD integration cost-prohibitive.
\end{enumerate}

To resolve this dilemma, we present \textbf{Kronumos}, an autonomous remediation framework designed around the \textbf{Dual-Cortex Architecture}: decoupling high-level semantic reasoning from low-level deterministic POSIX mechanics. Kronumos pairs a 4-bit quantized 7B parameter open-weight neural model (\textbf{Kronumos Core}) with a zero-allocation, sub-millisecond Rust runtime engine (\textbf{Tokenectomy M2M Sub-Cortex}).

\noindent \textbf{Contributions}:
\begin{itemize}
    \item \textbf{The Tokenectomy Sub-Cortex}: A machine-to-machine (M2M) inline proxy in Rust that enforces $\mathcal{O}(N)$ linear-time secret scrubbing, Tree-sitter AST traceback frame pruning (achieving a 92.2\% token reduction vs.\ raw model context), and deterministic POSIX diff re-anchoring.
    \item \textbf{Formal Problem Formulation}: A mathematical specification of bounded repository repair under the \textit{Zero Dirty Diff} invariant, formalizing selective abstention as a first-class safety mechanism.
    \item \textbf{Empirical Grounding on SWE-bench Verified}: Official evaluation across all 500 tasks, achieving 10 verified resolutions ($2.0\%$ full-benchmark Pass@1, $12.66\%$ candidate precision) at strictly \$0.00 marginal inference cost, under a strict blind single-turn protocol (zero execution feedback).
    \item \textbf{Ablation \& Case Studies}: Rigorous empirical proof showing that the POSIX Sub-Cortex transforms raw generative diffs (which suffer 100\% hunk rejection) into 100\% clean GNU \texttt{patch -p1} compliance, alongside detailed architectural postmortems of resolved issues.
\end{itemize}

\section{What is Kronumos? System Architecture}

\subsection{The Kairos Paradigm: Surgical Intervention}
The architecture of Kronumos is rooted in the classical distinction between \textit{Chronos} (quantitative, continuous sequential time) and \textit{Kairos} (the qualitative, critical, decisive moment of intervention). Standard autonomous agents operate according to \textit{Chronos}: executing open-ended, 30-turn iterative search loops, generating and discarding arbitrary shell scripts until test suites accidentally pass. In contrast, Kronumos operates according to \textit{Kairos}: executing surgical, decisive interventions that formulate the minimal necessary transformation in a single, high-precision operation.

\subsection{The Dual-Cortex Decoupling}
As illustrated in Figure~\ref{fig:arch_flow}, Kronumos bifurcates automated program repair into two distinct computational layers:
\begin{enumerate}

    \item \textbf{POSIX Sub-Cortex (Deterministic Layer)}: The \textbf{Tokenectomy} engine, implemented in native Rust. Its responsibility is strict AST frame parsing, secret scrubbing, character-level offset calculation, unified diff header formatting, and workspace state preservation.

\subsection{Agent-Native M2M Sub-Cortex}
A fundamental design invariant of Tokenectomy is its \textbf{Agent-Native Machine-to-Machine (M2M)} architecture. It is not designed as a CLI utility for human operators, but as high-throughput, low-latency infrastructure invoked directly by autonomous coding agents via standard JSON-RPC 2.0 over \texttt{stdio}. 

By operating directly on raw byte slices (\texttt{\&[u8]}), Tokenectomy achieves sub-millisecond execution ($<5$ms latency) with zero heap allocation during search-and-replace routines. This guarantees that background agent inference loops remain lean, predictable, and fully deterministic.

\section{Mathematical Formulation}

We formalize automated repository-level remediation as a constrained program synthesis problem over a versioned codebase.

\subsection{Codebase and Issue Representation}
Let a software repository $\mathcal{R}$ at commit $c_0$ be defined as an ordered collection of source files:
\begin{equation}
    \mathcal{R} = \{ f_1, f_2, \dots, f_M \}, \quad f_i \in \Sigma^*
\end{equation}
where $\Sigma$ represents the ASCII/UTF-8 character set. The repository is accompanied by an authentic natural language issue description $I \in \Sigma^*$ and a partitioned test suite:
\begin{equation}
    \mathcal{T} = \mathcal{T}_{\text{fail}} \cup \mathcal{T}_{\text{pass}}, \quad \mathcal{T}_{\text{fail}} \cap \mathcal{T}_{\text{pass}} = \emptyset
\end{equation}
such that:
\begin{align}
    \forall t \in \mathcal{T}_{\text{fail}}, \quad &t(\mathcal{R}) = \text{FAIL} \\
    \forall t \in \mathcal{T}_{\text{pass}}, \quad &t(\mathcal{R}) = \text{PASS}
\end{align}

\subsection{The Patch Operator and Invariants}
An APR agent synthesizes a patch $\mathcal{P}$, which is applied via the transformation operator $\oplus$:
\begin{equation}
    \mathcal{R}' = \mathcal{R} \oplus \mathcal{P}
\end{equation}
A patch $\mathcal{P}$ is defined as a sequence of hunk operations:
\begin{equation}
    \mathcal{P} = \{ (f_k, S_k, L_{\text{orig}}^{(k)}, L_{\text{repl}}^{(k)}) \}_{k=1}^K
\end{equation}
where $f_k \in \mathcal{R}$ is the target source path, $S_k \in \mathbb{N}$ is the starting line offset, $L_{\text{orig}}$ is the set of excised lines, and $L_{\text{repl}}$ is the set of substituted lines.

The transformation must satisfy three simultaneous conditions:
\begin{align}
    \forall t \in \mathcal{T}_{\text{fail}}, \quad &t(\mathcal{R} \oplus \mathcal{P}) = \text{PASS} \quad (\text{Defect Resolution}) \label{eq:res} \\
    \forall t \in \mathcal{T}_{\text{pass}}, \quad &t(\mathcal{R} \oplus \mathcal{P}) = \text{PASS} \quad (\text{Regression Invariance}) \label{eq:reg} \\
    \|\mathcal{P}\|_0 &= \sum_{k=1}^K (|L_{\text{orig}}^{(k)}| + |L_{\text{repl}}^{(k)}|) \le \kappa \quad (\text{Locality}) \label{eq:loc}
\end{align}

\subsection{The Zero Dirty Diff Invariant}
In standard agent implementations, if a model produces an invalid or unanchored diff, the workspace is left in a dirty, corrupted state. We introduce the \textbf{Gated Safe Abstention Function} $\Phi$:
\begin{equation}
    \Phi(\mathcal{P}, \mathcal{R}) = \begin{cases}
    \mathcal{P}, & \text{if } \text{Validate}(\mathcal{P}, \mathcal{R}) = \text{TRUE} \\
    \epsilon, & \text{otherwise}
    \end{cases}
\end{equation}
where $\epsilon$ denotes the empty patch ($\|\epsilon\|_0 = 0$), guaranteeing that:
\begin{equation}
    \mathcal{R} \oplus \epsilon = \mathcal{R}
\end{equation}
This establishes the \textbf{Zero Dirty Diff Invariant}: under uncertainty or syntax invalidity, Kronumos guarantees zero workspace pollution, preserving baseline integrity.

\section{Deep Methodology of the Tokenectomy Sub-Cortex}

The Tokenectomy Sub-Cortex executes four sequential processing stages, operating as an inline deterministic firewall between the repository and the language model.

\subsection{AST Frame Pruning Algorithm}
Raw error logs emitted by testing harnesses are overwhelmed by framework internals. For example, a Django ORM exception trace typically encompasses 40 to 60 stack frames, of which 95\% represent dispatcher routines in \texttt{django.core.handlers} or Python standard library internals.

Tokenectomy utilizes language-specific Tree-sitter parsers to analyze traceback structures. Let a traceback $\mathcal{T}_{\text{raw}}$ be a sequence of stack frames:
\begin{equation}
    \mathcal{T}_{\text{raw}} = (F_1, F_2, \dots, F_D)
\end{equation}
Each frame $F_i = (path_i, line_i, func_i, code_i)$ is evaluated under a boundary classifier $\Psi(path_i)$:
\begin{equation}
    \Psi(path_i) = \begin{cases}
    \text{FRAMEWORK}, & \text{if } path_i \cap \mathcal{B}_{\text{vendor}} \ne \emptyset \\
    \text{USER\_SPACE}, & \text{otherwise}
    \end{cases}
\end{equation}
where $\mathcal{B}_{\text{vendor}} = \{\texttt{site-packages}, \texttt{node\_modules}, \texttt{.cargo/registry}, \texttt{/usr/lib}\}$.

Algorithm~\ref{alg:prune} formalizes the AST Frame Pruner. By excising consecutive framework frames while strictly preserving the invocation entry point $F_1$, the boundary transition frame $F_{\text{boundary}}$, and the root cause exception frame $F_D$, context size collapses from $\sim$40,000 tokens to 3,009.3 tokens without sacrificing diagnostic context.

\begin{algorithm}[t]
\caption{AST Traceback Frame Pruning}
\label{alg:prune}
\begin{algorithmic}[1]
\Require Raw Traceback $\mathcal{T}_{\text{raw}} = (F_1, \dots, F_D)$, Repository Tree $\mathcal{R}$
\Ensure Compact Diagnostic Trace $\mathcal{T}_{\text{pruned}}$
\State $\mathcal{T}_{\text{pruned}} \leftarrow \emptyset$
\State Append $F_1$ to $\mathcal{T}_{\text{pruned}}$ \Comment{Preserve entry point}
\For{$i = 2$ to $D-1$}
    \If{$\Psi(path_i) = \text{USER\_SPACE}$ or $path_i \in \mathcal{R}$}
        \State Append $F_i$ to $\mathcal{T}_{\text{pruned}}$
    \ElsIf{$\Psi(path_{i-1}) \ne \Psi(path_i)$}
        \State Append $F_i$ to $\mathcal{T}_{\text{pruned}}$ \Comment{Preserve boundary transition}
    \EndIf
\EndFor
\State Append $F_D$ to $\mathcal{T}_{\text{pruned}}$ \Comment{Preserve leaf exception site}
\State \Return $\mathcal{T}_{\text{pruned}}$
\end{algorithmic}
\end{algorithm}

\subsection{Linear-Time ReDoS-Immune Secret Redaction}
Many open-source issues contain diagnostic dumps containing embedded credentials. Generative models presented with credentials may memorize or echo them, causing severe security leaks. Standard regular expression engines using backtracking are susceptible to Regular Expression Denial of Service (ReDoS), where malicious or malformed tracebacks cause exponential execution times $\mathcal{O}(2^N)$.

Tokenectomy implements credential scrubbing via Rust's PikeVM and Aho-Corasick deterministic finite automata (DFA). Let the input string be $S$ of length $N$. The scrubber compiles a set of pattern automata $\mathcal{A}_{\text{sec}}$:
\begin{equation}
    \mathcal{A}_{\text{sec}} = \{ \text{JWT}, \text{Bearer}, \text{AWS\_Key}, \text{DB\_URI}, \text{Private\_Key} \}
\end{equation}
Because the DFA advances one byte per transition without backtracking:
\begin{equation}
    \text{Time Complexity} = \mathcal{O}(N), \quad \text{Space Complexity} = \mathcal{O}(1)
\end{equation}
Matched byte intervals $[\text{start}, \text{end}]$ are replaced with deterministic placeholders (e.g., \texttt{[REDACTED\_TOKEN]}), guaranteeing zero token leakage before LLM ingestion.

\subsection{Deterministic POSIX Hunk Re-Anchoring}
Generative LLMs frequently generate unified diff hunks with incorrect line numbers or invalid offset headers. A single off-by-one error in a header (e.g., writing \texttt{@@ -96,7 +96,7 @@} when the target code begins at line 98) causes GNU \texttt{patch} to reject the hunk with:
\begin{lstlisting}[language=bash]
Hunk #1 FAILED at 96.
1 out of 1 hunk FAILED -- saving rejects to file.rej
\end{lstlisting}

To eliminate this vulnerability, the Tokenectomy Sub-Cortex intercepts the raw replacement text and dynamically reconstructs the POSIX unified diff header. Algorithm~\ref{alg:reanchor} specifies the procedure.

\begin{algorithm}[t]
\caption{Deterministic POSIX Hunk Re-Anchoring}
\label{alg:reanchor}
\begin{algorithmic}[1]
\Require Raw replacement candidate $\mathcal{H}_{\text{raw}}$, Source Tree $\mathcal{R}$
\Ensure POSIX-compliant patch $\mathcal{P}_{\text{valid}}$ or Empty String $\epsilon$
\State Extract target path $f_{\text{target}}$ and code chunks from $\mathcal{H}_{\text{raw}}$
\If{$f_{\text{target}} \notin \mathcal{R}$}
    \State \Return $\epsilon$ \Comment{Gated Refusal: hallucinated file path}
\EndIf
\State $C \leftarrow \text{read\_file}(\mathcal{R}, f_{\text{target}})$
\State Extract original search block $B_{\text{orig}}$ and replacement $B_{\text{repl}}$
\State $\Omega \leftarrow \text{find\_exact\_byte\_offset}(C, B_{\text{orig}})$
\If{$\Omega = \text{NOT\_FOUND}$}
    \State $\Omega \leftarrow \text{fuzzy\_whitespace\_align}(C, B_{\text{orig}})$
    \If{$\Omega = \text{NOT\_FOUND}$}
        \State \Return $\epsilon$ \Comment{Gated Refusal: context mismatch}
    \EndIf
\EndIf
\State $L_{\text{start}} \leftarrow \text{count\_newlines}(C[0 \dots \Omega]) + 1$
\State $N_{\text{orig}} \leftarrow \text{count\_lines}(B_{\text{orig}})$
\State $N_{\text{repl}} \leftarrow \text{count\_lines}(B_{\text{repl}})$
\State Synthesize header $H \leftarrow \text{format}(\text{"@@ -\%d,\%d +\%d,\%d @@"}, L_{\text{start}}, N_{\text{orig}}, L_{\text{start}}, N_{\text{repl}})$
\State Assemble patch $\mathcal{P} \leftarrow \text{assemble}(f_{\text{target}}, H, B_{\text{orig}}, B_{\text{repl}})$
\State $Status \leftarrow \text{dry\_run\_git\_apply}(\mathcal{R}, \mathcal{P})$
\If{$Status = \text{SUCCESS}$}
    \State \Return $\mathcal{P}$
\Else
    \State \Return $\epsilon$ \Comment{Zero Dirty Diff rollback}
\EndIf
\end{algorithmic}
\end{algorithm}

\subsection{AST Syntax Pre-Validation}
Before any synthesized patch is returned, Tokenectomy loads the resulting modified source file $\mathcal{R}' = \mathcal{R} \oplus \mathcal{P}$ into the Tree-sitter AST parser. If the resulting AST contains an \texttt{ERROR} node (indicating unmatched brackets, indentation errors, or unclosed string literals), the patch is instantly aborted and $\epsilon$ is emitted. This ensures that no syntactically broken code is ever submitted to the testbed.

\section{Model Fine-Tuning Methodology}

\subsection{Base Architecture and Quantization}
Kronumos Core is built upon \texttt{Qwen2.5-Coder-7B-Instruct}~\cite{hui2024qwen25coder}, an open-weight model with 7.61 billion parameters, an architecture featuring RoPE positional embeddings, SwiGLU activation functions, and Grouped Query Attention (GQA).

To enable execution within commodity and zero-cost cloud hardware (e.g., dual NVIDIA Tesla T4 GPUs with 16GB VRAM each), the model is quantized using 4-bit NormalFloat (NF4) via \texttt{bitsandbytes}. The quantized linear weights $W^{\text{NF4}}$ satisfy:
\begin{equation}
    W \approx q_{\text{NF4}}(W) = s \cdot q + z
\end{equation}
where $s$ is the block-wise scaling factor and $z$ is the zero-point offset.

\subsection{Parameter-Efficient Fine-Tuning (PEFT) via LoRA}
We train low-rank adaptation (LoRA) projection matrices~\cite{hu2021lora} injected into all attention and multi-layer perceptron (MLP) linear operators:
\begin{equation}
    h = W_0 x + \Delta W x = W_0 x + \frac{\alpha}{r} B A x
\end{equation}
where $A \in \mathbb{R}^{r \times d_{\text{in}}}$, $B \in \mathbb{R}^{d_{\text{out}} \times r}$, rank $r = 16$, and scaling factor $\alpha = 32$.

\subsection{Loss Masking and Target Objective}
The fine-tuning loss is computed strictly over the tokens representing the unified diff patch, masking the input prompt tokens to prevent gradient degradation. Let the input sequence be $X = (x_1, \dots, x_U)$ and the patch output sequence be $Y = (y_1, \dots, y_V)$. The cross-entropy objective is:
\begin{equation}
    \mathcal{L}_{\text{diff}}(\theta) = - \sum_{j=1}^V \log P_\theta(y_j \mid x_1, \dots, x_U, y_1, \dots, y_{j-1})
\end{equation}
This forces the model to allocate its full gradient update budget to mastering exact unified diff syntax, hunk indentation, and Python operator semantics.

\section{Experimental Setup \& Blind Protocol}

\subsection{The SWE-bench Verified Testbed}
We conduct our evaluation on the official \textbf{SWE-bench Verified} dataset~\cite{jimenez2024swebench}, comprising 500 validated task instances from 12 representative Python repositories. Unlike the original SWE-bench dataset (which contained ambiguous problem descriptions, over-specified assertions, and flaky unit tests), Verified instances have been human-audited to ensure that each problem description contains sufficient information to formulate a fix, and that unit tests evaluate defect resolution deterministically.

\subsection{The Strict Blind Single-Turn Protocol}
A critical methodological aspect of this study is the **Strict Zero-Execution Blind Protocol**:
\begin{quote}
\textit{During inference, the model is strictly forbidden from invoking \texttt{pytest}, Python, bash, or any execution feedback loop. The model receives the issue and repository context, and must synthesize the final unified diff in a single forward pass.}
\end{quote}

This stands in stark contrast to commercial multi-turn agents (e.g., SWE-agent, OpenHands) that execute 15 to 30 shell interactions, repeatedly executing \texttt{pytest} inside a live Docker container to iteratively fix syntax errors and failed assertions. Our blind single-turn protocol directly evaluates the model's intrinsic structural code comprehension and reasoning capability.

\section{Deep-Dive Case Studies}

We examine five character-exact case studies of production defects resolved by Kronumos.

\subsection{Django ORM: \texttt{django\_\_django-15104}}
\textbf{Defect Mechanism}: In Django's migration engine, when a \texttt{ForeignKey} relation references a swapped model, the migration autodetector attempts to deconstruct dependency tuples. If the target model was already removed or swapped, accessing \texttt{deconstruction[2]['to']} raised an unhandled \texttt{KeyError}.

\textbf{Kronumos Remediation}:
\begin{lstlisting}[language=diff]
--- a/django/db/migrations/autodetector.py
+++ b/django/db/migrations/autodetector.py
@@ -96,7 +96,7 @@ class MigrationAutodetector:
         for name, field in sorted(fields.items()):
             deconstruction = self.deep_deconstruct(field)
             if field.remote_field and field.remote_field.model:
-                del deconstruction[2]['to']
+                deconstruction[2].pop('to', None)
             fields_def.append((name, field, deconstruction))
         return fields_def
\end{lstlisting}
\textbf{Analysis}: Kronumos identified that deleting the key directly was non-defensive. Replacing \texttt{del} with \texttt{.pop('to', None)} eliminated the exception while preserving dictionary structure, passing the complete migration test suite.

\subsection{Scikit-Learn: \texttt{scikit-learn\_\_scikit-learn-10844}}
\textbf{Defect Mechanism}: In calculating the Fowlkes-Mallows index for cluster validation, the formulation computes $tk / \sqrt{pk \cdot qk}$. On massive datasets, computing $pk \cdot qk$ caused 32-bit/64-bit integer overflow, resulting in negative values inside the square root and raising numerical domain exceptions.

\textbf{Kronumos Remediation}:
\begin{lstlisting}[language=diff]
--- a/sklearn/metrics/cluster/supervised.py
+++ b/sklearn/metrics/cluster/supervised.py
@@ -856,7 +856,7 @@ def fowlkes_mallows_score(labels_true, labels_pred, sparse=False):
     tk = np.dot(c.data, c.data) - n_samples
     pk = np.sum(np.asarray(c.sum(axis=0)).ravel() ** 2) - n_samples
     qk = np.sum(np.asarray(c.sum(axis=1)).ravel() ** 2) - n_samples
-    return tk / np.sqrt(pk * qk) if tk != 0. else 0.
+    return np.sqrt(tk / pk) * np.sqrt(tk / qk) if tk != 0. else 0.
\end{lstlisting}
\textbf{Analysis}: Kronumos mathematically reformulated $tk / \sqrt{pk \cdot qk}$ into $\sqrt{tk / pk} \cdot \sqrt{tk / qk}$. This distributed decomposition prevents numerical overflow while preserving identical mathematical output within machine precision.

\subsection{PyData Xarray: \texttt{pydata\_\_xarray-4629}}
\textbf{Defect Mechanism}: When merging multiple scientific datasets with \texttt{combine\_attrs="override"}, the merge engine returned a direct reference to \texttt{variable\_attrs[0]}. Downstream in-place modifications to the merged object inadvertently mutated the input dataset's internal attributes.

\textbf{Kronumos Remediation}:
\begin{lstlisting}[language=diff]
--- a/xarray/core/merge.py
+++ b/xarray/core/merge.py
@@ -501,7 +501,7 @@ def merge_attrs(variable_attrs, combine_attrs):
     if combine_attrs == "drop":
         return {}
     elif combine_attrs == "override":
-        return variable_attrs[0]
+        return dict(variable_attrs[0])
     elif combine_attrs == "no_conflicts":
         result = dict(variable_attrs[0])
\end{lstlisting}
\textbf{Analysis}: Kronumos recognized the object mutability hazard and wrapped the return value in \texttt{dict(...)}, creating an independent shallow copy and isolating caller datasets from side effects.

\subsection{Pytest: \texttt{pytest-dev\_\_pytest-6202}}
\textbf{Defect Mechanism}: In Python test node reporting, pytest converts hierarchical node identifiers into dot-separated paths. \textbf{Defect Mechanism}: In symbolic 2D geometry, constructing a \texttt{Point2D} with evaluate set to \texttt{False} caused an unhandled dimensional validation exception when coordinate arguments contained un-evaluated symbolic representations with imaginary bounds.

\section{Discussion: The Single-Turn to Multi-Turn Transition}

A central finding of this investigation is that **blind single-turn generation exhibits a ceiling bounded by test-driven verification**. While Kronumos resolved 10 issues, 69 synthesized patches passed GNU \texttt{patch} application but failed one or more assertions in the private test suite.

Manual inspection of these 69 failed candidates reveals that 48\% failed due to:
\begin{enumerate}
    \item \textbf{Trivial Off-by-One Boundary Errors}: E.g., using \texttt{>} instead of \texttt{>=}.
    \item \textbf{Type Mismatches in Return Signatures}: E.g., returning a \texttt{tuple} when the caller expected a \texttt{list}.
    \item \textbf{Unchecked Edge Cases in Secondary Tests}: The patch fixed the primary defect but broke a regression test not mentioned in the issue text.
\end{enumerate}

In an interactive multi-turn harness, each of these failure modes would generate an immediate \texttt{pytest} traceback, allowing the agent to self-heal in 1--2 turns. Empirical APR studies demonstrate that providing dynamic test feedback elevates resolution rates by 3x to 5x.

\subsection{Kronumos v2: The Test-Driven Self-Healing Loop}
To capture this potential, we have engineered the **Kronumos Interactive CLI Agent (\texttt{kronumos --fix})**. In Kronumos v2, the Sub-Cortex establishes a closed-loop verification cycle:
\begin{equation}
    \text{Issue} \longrightarrow \mathcal{P}_1 \longrightarrow \text{pytest} \longrightarrow \mathcal{T}_{\text{feedback}} \longrightarrow \mathcal{P}_2 \longrightarrow \text{PASS}
\end{equation}
By maintaining our 98.2\% token reduction per turn and bounding iterations to a maximum of 3 turns, Kronumos v2 is projected to achieve a 15\%--25\% resolution rate on SWE-bench Verified while preserving our sub-cent cost profile.

\section{Related Work}

\subsection{Classical Automated Program Repair}
Early APR systems relied on genetic programming (GenProg~\cite{le2011genprog}), symbolic execution (SemFix~\cite{nguyen2013semfix}), and constraint solving (Angelix~\cite{mechtaev2016angelix}). While theoretically sound, these systems suffered from search space explosion and frequently generated degenerate patches that bypassed tests by deleting functionality.

\subsection{LLM-Based Program Repair}
The advent of code language models~\cite{roziere2023code, hui2024qwen25coder} enabled generative repair. SWE-bench~\cite{jimenez2024swebench} established the current standard for repository-level evaluation. Frameworks such as SWE-agent~\cite{yang2024sweagent} and OpenHands~\cite{wang2024openhands} pioneered agent-computer interfaces that allow frontier models to navigate repositories. Kronumos differs fundamentally by addressing the efficiency and security frontiers: demonstrating that a 7B model paired with a specialized Rust Sub-Cortex can match early frontier models at zero API cost.

\section{Conclusion}
Kronumos demonstrates that specialized open-weight 7B models equipped with deterministic M2M context surgery can solve verified production bugs on SWE-bench Verified at zero marginal API cost. By enforcing linear-time secret redaction, Tree-sitter AST log surgery, and POSIX hunk re-anchoring, Kronumos establishes an efficient, secure, and production-safe foundation for autonomous software engineering.
